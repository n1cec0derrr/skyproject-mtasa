# Лаунчер и обновления Sky Project

Как сейчас устроен клиент и что лаунчер должен доставлять игрокам. Сборка самого клиента — в `BUILD_SKY_RU.md`.

## Что лежит у игрока

```
<папка игры>\
    Sky Project.exe                 клиент MTA (из Bin после сборки)
    MTA\ ...                        модули и данные MTA
    mods\deathmatch\ ...            client.dll и Lua
    dlc\
        sky_project.skydlc          весь контент Sky Project: карта, машины, данные (~2,3 ГБ)
        zz_*.skydlc                 патчи поверх него (скины, машины, правки), маленькие
    runtime\GTA San Andreas\        GTA SA 1.0 без .img + лимит-аджастер + звук Sky Project
```

Не раздавать (создаются у игрока сами или нужны только разработчику):
`Bin\server\`, все `*.pdb`, `*.lib`, `*.exp`, `MTA\logs\`, `MTA\dumps\`, `MTA\config\coreconfig.xml`
(настройки игрока: при первом запуске клиент создаст свои, по умолчанию 16:10; память подгрузки с пакетами DLC всегда не больше 512 МБ, иначе 32-битная игра упирается в 4 ГБ).

## Как работают пакеты

- Клиент при запуске подключает все `dlc\*.skydlc` по алфавиту. Файл из более позднего пакета
  перекрывает такой же файл из более раннего. Поэтому патчи называются `zz_<что-то>.skydlc`:
  они идут после `sky_project.skydlc` и заменяют его файлы.
- Пакет — это обычный файл. Лаунчеру не нужно ничего о нём знать: скачать и положить в `dlc`.
- Удалить патч = удалить файл из `dlc`.
- Пакеты зашифрованы ключом, вшитым в клиент. Пакеты, собранные другим ключом, клиент не откроет
  (в `MTA\logs\logfile.txt` будет `SkyDLC: rejected package`).

## Виды обновлений

| Что меняется | Что делать | Что качает игрок |
|---|---|---|
| Скрипты, интерфейс, логика (ресурсы сервера) | Залить ресурс на сервер, `restart <ресурс>` | Ничего от лаунчера: MTA сам скачает ресурс при входе |
| Новая машина, скин, замена модели | Собрать патч в Sky DLC Studio («Патч из папки…») → `zz_<имя>.skydlc` | Один маленький файл |
| Правка карты, `gta.dat`, `.ide`, `.ipl`, `timecyc.dat` и т. п. | Патч с этими файлами (те же пути, что в игре: `data\...`) | Один маленький файл |
| Много патчей накопилось | Изредка пересобрать `sky_project.skydlc` целиком, патчи удалить | ~2,3 ГБ, поэтому редко |
| Клиент (`core.dll`, `client.dll` и т. д.) | Собрать по `BUILD_SKY_RU.md`, разослать изменившиеся файлы | Несколько файлов, обычно до 10 МБ |

Модели ресурсов (машины `sky_carshop`, скины `sky_skins`) лежат в пакетах по пути
`resources/<ресурс>/<путь из скрипта>`, например `resources/sky_skins/models/bee.dff`.
В самих ресурсах на сервере этих файлов нет, игроки их с сервера не качают.

## Что должен уметь лаунчер

1. Скачать с сайта список файлов (манифест): путь, размер, SHA-256 каждого файла клиента и пакетов.
2. Сравнить с файлами у игрока и скачать только отличающиеся и недостающие.
3. Удалить из `dlc` пакеты, которых больше нет в манифесте (иначе старый патч продолжит перекрывать файлы).
4. Запустить `Sky Project.exe` (можно с адресом сервера: `Sky Project.exe mtasa://51.75.44.11:22003`).

Хостинг: любой HTTP-сервер или CDN. GitHub Releases для `sky_project.skydlc` не подходит:
там ограничение 2 ГБ на файл, а пакет больше.

Скачивать лучше во временный файл и подменять после проверки SHA-256: обрыв загрузки
посреди `sky_project.skydlc` клиент просто отклонит, но игроку придётся качать заново.

## Проверка версии на сервере

Сервер (`play_main\server\spawn.lua`) пускает только клиент с версией `1.6.0-5.24147.0`.
Эту строку сообщает `MTA\netc.dll`, а не наш код. Если при сборке клиента скачается более новый
`netc.dll`, версия изменится и игроков начнёт кикать. Раздавайте тот `netc.dll`, с которым
проверяли, а при его обновлении поменяйте строку на сервере (кикнутая версия пишется
в `server.log` строкой `[version] kick ...`).
